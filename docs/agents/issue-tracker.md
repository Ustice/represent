# Issue tracker: GitHub

Use `gh` and infer the repository from `git remote -v`. Read an issue with
`gh issue view <number> --comments`. Prefer structured JSON for queries and
`--body-file` for multiline issue or PR text.

When asked to create or update tracked work, use GitHub Issues. Do not maintain
a parallel local tracker. Use the optional issue form when helpful; ordinary
prose is fine. A direct task does not require a new issue or label first.
